# Page Accessibility Requirements

These requirements ensure that the web application is accessible to all users, including those with visual, auditory, motor, and cognitive impairments. All development must adhere to WCAG 2.1 Level AA standards at a minimum.

## 1. Semantic HTML & Structure
- **Use Native Elements**: Use `<button>`, `<a>`, `<input>`, `<select>`, and `<textarea>` for interactive elements. Avoid using `<div>` or `<span>` with click handlers unless absolutely necessary (and if used, must have appropriate ARIA roles and keyboard support).
- **Landmark Regions**: Organize the page using landmark elements: `<header>`, `<nav>`, `<main>`, `<aside>`, `<section>`, and `<footer>`.
- **Heading Hierarchy**: Use a single `<h1>` for the page title. Maintain a logical heading structure (`<h2>` through `<h6>`) without skipping levels.
- **Lists**: Use `<ul>`, `<ol>`, and `<li>` for grouped items to provide context to screen readers.

## 2. Keyboard Navigation
- **Focus Indicators**: Every interactive element must have a clearly visible focus state (outline). Never remove the default focus outline without providing a high-contrast alternative.
- **Logical Tab Order**: The `tabindex` must follow the visual flow of the page. Avoid using positive `tabindex` values.
- **Skip Links**: Provide a "Skip to Main Content" link at the very top of the page, visible on focus.
- **Keyboard Traps**: Ensure that modal dialogs or menus do not trap keyboard focus unless they are active, and provide an easy way to exit (e.g., `Esc` key).
- **Custom Widgets**: Any custom component (e.g., a color-coded URL fragment picker) must be fully operable via keyboard (`Enter`, `Space`, and Arrow keys where applicable).

## 3. ARIA (Accessible Rich Internet Applications)
- **Role usage**: Use ARIA roles (e.g., `role="dialog"`, `role="alert"`, `role="status"`) only when native HTML elements cannot provide the required semantics.
- **Labels**: Every interactive element must have an accessible name. Use `aria-label` for icons without text or `aria-labelledby` to link to existing text.
- **States**: Use `aria-expanded`, `aria-checked`, `aria-disabled`, and `aria-selected` to communicate the state of dynamic components.
- **Live Regions**: Use `aria-live="polite"` or `aria-live="assertive"` for dynamic updates (e.g., "Generated URL updated" or "Parsing complete") so screen readers announce changes without focus movement.

## 4. Visual Accessibility
- **Color Contrast**: Text and icons must have a minimum contrast ratio of 4.5:1 against their background (3:1 for large text).
- **Color Dependency**: Never use color as the *only* way to convey information (e.g., use icons or text labels alongside the color-coded URL fragments).
- **Theming & Disabilities**: Support high-contrast modes and ensure the design is usable for users with color vision deficiencies (protanopia, deuteranopia, tritanopia).
- **Dark/Light Mode**: Colors must be adjusted in both modes to maintain readability and contrast requirements.

## 5. Text & Layout Scalability
- **Text Sizing**: The layout must remain functional and readable when text size is increased up to 200%. Avoid fixed heights/widths that cause text to overflow or overlap.
- **Responsive Reflow**: The page must be usable on small screens (mobile) without loss of information or functionality. Horizontal scrolling should be avoided for primary content.
- **Touch Targets**: Ensure interactive elements have a minimum size of 44x44 pixels to accommodate users with limited motor control.

## 6. Forms & Inputs
- **Explicit Labels**: Every input must have a corresponding `<label>` linked via the `for` and `id` attributes.
- **Error Feedback**: Validation errors must be clearly identified with text, linked to the input via `aria-describedby`, and communicated to screen readers.
- **Instructional Text**: Provide clear instructions and examples for complex inputs (e.g., "Paste your URL here").

## 7. Internationalization (i18n) & Language
- **Language Attribute**: The `<html>` tag must have a valid `lang` attribute (e.g., `<html lang="en">`).
- **Dynamic Language Support**: When the UI language changes (English, Polish, German, Spanish, Italian), ensure that all ARIA labels and alt text are also translated.
- **RTL Support**: If supporting Right-to-Left languages, ensure layouts and directionality flip correctly.

## 8. Images & Multimedia
- **Alt Text**: All informative images must have descriptive `alt` text. Decorative images must have an empty `alt=""` attribute to be ignored by screen readers.
- **Icon Buttons**: Buttons that only contain an icon must have an `aria-label` or visually hidden text inside.
