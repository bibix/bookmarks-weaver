# Bookmarks weaver

The project is a bookmarks generator. It creates a bookmarks file that contains generated folders and bookmarks. 
The folder structure and all bookmark aspects are fully customizable through templating.  
The user can specify any folder and subfolder structure. Names of folders can be freely templated.
A dedicated component for bookmark templating allows the user to define bookmark name, url, list of tags and keywords.

## UI Sections
The page must be divided into sections. 
The sections must be clearly labeled and have a consistent layout. Each section has a short description.

Sections:
1. Output file name. 
2. Template section. A blocknote text component allows creation of template for folders and bookmarks. 
3. Variables section where user can add a table with values for the parameter defined in the template.
4. Generated output preview with download button on top of this section.

## Section details

### File name section 
File name for downloading the bookmarks. 
Use the default "bookmarks-{{yyyy}}-{{mm}}-{{dd}}.html"

### Template section
A dedicated blocknote text component that has three main custom components enabled. 
The only components that should be enabled are:
- comment component - allowing users to add comments anywhere in the structure
- folder component - allowing users to create folders. These look the same as unordered lists. The text value of the folder name is a template that uses handlebars syntax
- bookmark component - allowing users to create bookmarks. It has the fields in the following order:
  - bookmark title - can use handlebars syntax
  - bookmark url - can use handlebars syntax
  - bookmark description - can use handlebars syntax.
  - bookmark tags - It is a list of values. It can use handlebars syntax.
  - bookmark keywords - It is a list of values. It can use handlebars syntax.

Each handlebars value that is used in the templates in this section is parsed and validated. 
If the handlebars value is not valid, it is underlined with a red wiggly line.
If the handlebars value does not exist, it is underlined with a double orange wiggly lines.
A new variable is added or updated whenever the user uses the handlebars values.
Make sure that the components placeholder text disappears when the user starts typing.

### Variables section

Each variable is a separate blocknote component with a single table inside. The blocknote component does not allow adding anything. There is only a single table inside. 
When the variable is created, there is a single table with the name of the variable in the first column. There is only one column in the table.

Make sure that the header of the table has a different background and the letters are written in bold and monospace.
Each variable should have a different background color and wherever the variable is used in the template, it should have the same colour - including the handlebars.
The variable is a table with one or more columns.
If there is only one column, the user can use the table name directly in the template to access the value. 
The header of the table is the name of the variable.
For example:
```
https://localhost/{{ username }}
```

When there are multiple columns, the user must use table name and column name in the template. For example: 
```
{{ address.city }}-{{ address.street }}
```

User can add rows and columns to the variables table.

Allow renaming of the variable table and column names. Rename the template occurrences when the variable name changes.


### Generated results 

The generated results section contains a download button that triggers download of a generated bookmarks file.

The preview contains an expandable list of nested folders - as defined by the user, but with all the templates resolved to values from the variables tables.
Finally, each generated bookmark is displayed in the folder structure matching the user's template.
The bookmark displays title, description, tags, keywords, and the URL. All templates are resolved to values from the variables tables.

If there is a variable used in any folder or subfolder. The value of the variable from the table must be used to create separate folders.
Nested folders create extra nested looped structure.

## Variable resolution

For each variable table, the generator loops over all rows and uses the values to generate the folder structure and bookmarks.
